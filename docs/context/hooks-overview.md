# Hook scripts

This repository only tracks the scripts. Which of them are registered is decided by settings files outside the repository (the repo's `ai-code-agents/claude/settings.json` registers only `no-agent-mention.py`), so you cannot tell from the repo which hooks are active: check your own settings. "Event" below is where a script is meant to be registered, from its header comment, which is the detailed spec.

Scripts live in `ai-code-agents/claude/local-hooks/`, `hooks/` and `personal-hooks/`.

## Scripts
| Script | Event, matcher | What it does | Off switch |
|---|---|---|---|
| delegate-gate.sh | PreToolUse, Edit/Write/NotebookEdit (and Bash) | Denies file edits from the main session; on Bash denies redirects to files, tee, `sed -i`, `perl -i`, `awk -i inplace`. Subagents unaffected | CLAUDE_DELEGATE_GATE=off or 12h off-file |
| delegate-reminder.sh | UserPromptSubmit | One-line delegation reminder | same |
| require-agent-model.sh | PreToolUse, Agent/Task | Denies a subagent call without `model` (forks exempt) | same |
| read-size-gate.sh | PreToolUse, Read | Main session: denies text files over 300 lines or 30000 bytes without a limit of 300 or less | same; CLAUDE_READ_GATE_MAX_LINES / _MAX_BYTES change limits |
| worktree-gate.sh | PreToolUse, Edit/Write/NotebookEdit and Bash | Denies edits and HEAD/index/worktree-changing git commands in a primary checkout. The directory is the payload cwd followed through `cd`, `builtin cd`, `pushd`, `git -C`, `env -C` (also into a body) and `bash -c`/`sh -c`/`eval`/`env -S` bodies (3 levels, escaped quotes unescaped), with a literal path or a plain variable assignment certain to have run; a path not there yet is judged by its nearest existing ancestor. An explicit `GIT_DIR=`, `--git-dir`, `GIT_WORK_TREE=` or `--work-tree` is judged by its work tree (the work-tree value, else the parent of a git directory named `.git`, else what git reports); a linked worktree's git directory is allowed. When the directory cannot be established (variable not certain, substitution, `cd -`, `popd`, variable git directory, an unparseable wrapper body holding a git command, a line with over about 300 commands or 0.4 s of analysis that holds one) a checkout-changing command is denied: the gate could not tell which checkout, write the directory literally. A directory made by a bare `mktemp -d` on the same line is allowed; any `-p`, template, `--tmpdir`, `-t`, `-u`, `--suffix`, TMPDIR named anywhere on the line (`: ${TMPDIR:=...}` included), an `ln`, `mv`, `rm`, `rmdir` or `mount` anywhere on the line (a symlink could lead out), or a gate temp root inside a git work tree (asked of git; a stray empty `.git` directory is not one) makes it unknown, so such forms are denied. A bare repository given through `GIT_DIR=` is denied for a checkout-changing command (no work tree can be worked out). Read-only git commands (including `am`/`rebase --show-current-patch`) and a payload with no cwd are not judged. Limits: nesting deeper than 3, aliases, `xargs`/`find -exec`/`ssh` and text fed to a shell (`echo 'cd <path> && git commit'` piped into bash; git-guard does follow it for its text-only rules) are not followed | CLAUDE_WORKTREE_GATE=off or 12h off-file |
| git-guard.sh | PreToolUse, Bash | Denies hook bypass (`--no-verify`, `commit -n`, `HUSKY=0`, core.hooksPath), force push, push to the default branch. A lease-only force push (`--force-with-lease`, `--force-if-includes`) is denied unless HEAD has a valid check stamp, then it answers "ask"; an ask never stops the rest of the line being judged. Stamps are unsigned: a guardrail, not a seal. The text-only rules (bypass, force push, `--all`, `--mirror`) also apply inside `bash -c`/`sh -c`/`eval`/`env -S` bodies (3 levels, escaped quotes unescaped), behind prefix commands (`timeout 5`, `nice -n`, `stdbuf`, `setsid`, `ionice`, `doas`, `sudo -u`, `env`, `builtin`), with `GIT_DIR=`, `GIT_WORK_TREE=`, `--git-dir`, `--work-tree` or `env -C`, in text fed to a shell (`echo '...'` piped into bash, `bash <<< '...'`, a here-document into bash/sh) and on a line over the analysis budget (about 300 commands or 0.4 s: only these rules, from one cheap pass). An unparseable wrapper body that holds a push or hook bypass is denied (`unparsed-body`). When the directory is unknown (variable not certain, substitution, `cd -`, explicit git dir, even a `mktemp -d` one: a clone there can still push to a real remote) a push is denied if it names `main` or `master` (also `heads/main`), names no destination (bare `git push`, `git push origin`, `HEAD`, `@`, a bare `:`), and allowed if it names another branch, `--repo=<remote> feat` or `tag v1`; the lease rule already denied an unknown directory. Plain variable assignments certain to have run are resolved like a literal path; a path not there yet is judged by its nearest existing ancestor. Limits: nesting deeper than 3, aliases, `xargs`/`find -exec`/`ssh`, text a shell reads from a file or a command's output are not followed; with an unknown directory only `main` and `master` are known as default branch names | CLAUDE_GIT_GUARD=off or 12h off-file |
| checks-gate.sh | PreToolUse, Bash | Before `git push` and `gh pr create`, wants a valid check stamp for HEAD; warns (default) or denies by `~/.claude/checks-gate.conf` (`MODE`, `DENY_AFTER`). Silent when the repo has no checks or the branch since its merge base with the default branch is docs only; a broken check configuration counts as no record. Skips dry-run, delete, tags-only, other refs, `gh pr create --repo`. When the directory cannot be established (a `cd`, `pushd`, `-C`, `--git-dir`, `--work-tree` or `GIT_DIR=` with a variable or substitution, `cd -`, `popd`, or a `bash -c`/`sh -c`/`eval` body doing so) it denies or warns that it could not tell which repository the command runs in; only text-only exemptions (dry-run, delete, tags-only) still apply, and a plain literal assignment earlier in the line (`W=/path; cd "$W"`) is resolved. Variables resolve only from a standalone literal assignment certain to have run (not a prefix assignment, not inside if/loop/function/subshell/pipeline, not after an and-or operator following another command, not after unset/read/+=/declare/let/`(( ))`/...); any `--git-dir`, `--work-tree`, `GIT_DIR=` or `GIT_WORK_TREE=` on a push also counts as unknown. A line with over about 300 git/gh/cd/shell words is not walked (the walker is quadratic): a push or `gh pr create` on it counts as an unknown directory, otherwise it is silent (4,000 commands: about 50 ms). Walker: `_cmd_dirs.py` (legacy mode, behaviour unchanged; a `mktemp -d` directory counts as unknown here). Limits: an unparseable command line, `bash -c`/`eval` nesting deeper than 3, aliases, `xargs`/`find -exec`/`ssh` wrappers lines over about 128 KB and word splitting under a changed `IFS` are not scanned; a `cd` to a missing directory or after `false &&` is followed as if it ran (as before). Read-only | CLAUDE_CHECKS_GATE=off |
| commit-gate.sh | PreToolUse, Bash | Before `git commit` (not `--dry-run`). Denies: secret file names (`.env`, `.env.*`, `*.pem`, `*.key`, `id_rsa*`, `id_ed25519*`, `credentials.json`, `*.p12`, `*.pfx`; not `.env.example` style files or `*.pub`; `.npmrc` only with a literal `_authToken`), conflict markers (both `<<<<<<< ` and `>>>>>>> ` in added lines, not in docs files), a high-confidence secret in added lines or in the message. Judges staged paths, `commit -a`, a path-limited commit (named paths only), and files a same-line `git add` will stage (a glob or non-literal argument counts like `add -A`). Warns only (never denies) on subject format where the repo already follows `type(scope): description`. A file with over 2 MB of added text (or an `.npmrc` over 64 KB) is skipped with a warning naming how many files were not scanned; the rest are still scanned, however large their neighbours are (skipped files do not use the scan budget). A path the commit deletes is never judged. A path-limited commit of a directory or glob also covers staged files; a repository with no commits is compared with the empty tree. Config `~/.claude/git-gates.conf` (`ALLOW_PATHS`). Read-only, fail open | CLAUDE_GIT_GUARD=off or the git-guard 12h off-file |
| pr-gate.sh | PreToolUse, Bash | On `gh pr create`, `gh issue create` and `gh pr edit` with a body or title. Always denies: `gh pr create` from a head branch that is not pushed and in sync (judged from `refs/remotes/<push remote>/<branch>`, else a differently named upstream; an upstream that is the default branch does not count as pushed), and a secret in the title or body. By mode (`PR_GATE_MODE=warn` default, `deny`, `PR_GATE_DENY_AFTER`): missing template sections, unfilled template placeholders, a diff over the size cap without a Split plan or `LOC-exception:`. Skips `--web`, `--fill*`, `--template`, unreadable bodies and `-R` naming another repo. Local refs only, no network. Config `~/.claude/git-gates.conf` (`SOP_REPOS`, `SOP_PR_TEMPLATE`, `SOP_ISSUE_TEMPLATE`, `OPTIONAL_HEADINGS`, `LOC_CAP`, mode keys); `git-gates.conf.example`. Skipped on a detached HEAD; empty sections pass | CLAUDE_PR_GATE=off |
| public-repo-text-gate.sh | PreToolUse, Bash | On public repos denies private hostnames, IPs, emails, configured terms in commit, tag and gh pr/issue text | CLAUDE_PUBLIC_TEXT_GATE=off or 12h off-file |
| shared-db-write-gate.sh | PreToolUse, MCP tools ending execute_sql or apply_migration | Ownership, project-lookup, generated-column and no-schema-change rules for writes to a shared database | CLAUDE_SHARED_DB_GATE=off or 12h off-file; inactive without its config file |
| require-acceptance-criteria.sh | PreToolUse, Agent | Main-session calls only (returns early when the payload has an agent id): denies a brief to a non-exempt subagent type with no "Done when" style section | CLAUDE_ACCEPTANCE_GATE=off or 12h off-file (shared with handback-gate) |
| handback-gate.sh | PreToolUse SubagentHandback, and SubagentStop | Sends back a report lacking an Acceptance check section, containing a "not met" line, lacking a `Context docs:` line, or over 4000 characters; two send-backs, then it passes | CLAUDE_ACCEPTANCE_GATE=off or the shared 12h acceptance off-file disables all of these checks together, including the size limit (it exits before the size check) |
| context-docs-start.sh | SessionStart, SubagentStart | Injects the first 3000 characters of `docs/context/INDEX.md`, plus standing subagent instructions | CLAUDE_ACCEPTANCE_GATE=off or a fresh acceptance off-file drops the acceptance instruction |
| enforce-response-cap.sh | Stop | Nags once when a reply exceeds 1200 characters outside code blocks | an approval recorded by reply-cap-prompt.sh |
| reply-cap-prompt.sh | UserPromptSubmit | States the cap; records approvals for a long reply ("go long", "tell me more", "elaborate", ...; "limit off" until "limit on") | the approval phrases |
| clock-reminder.sh | SessionStart, UserPromptSubmit | Reminders by local time from a local config file, once per day each | no config file means no output |
| behavior-doc-reminder.sh | PreToolUse and PostToolUse on Bash; first argument `pre` or `post` | Warn-only nudge to document behavior changes around commit, push and PR create | none |
| ../hooks/no-agent-mention.py | PreToolUse, Bash | Denies commits and `gh pr` text that credit a coding agent | none |
| ../personal-hooks/sync-memory.sh | SessionStart | Keeps per-project memory folders of two config dirs symlinked | none |

The 12h off-file: a file under `~/.claude/` (path overridable by an environment variable named in the script: `CLAUDE_PUBLIC_TEXT_GATE_OFF_FILE` for `public-text-gate.off`, `CLAUDE_SHARED_DB_GATE_OFF_FILE` for `shared-db-gate.off`, `CLAUDE_ACCEPTANCE_GATE_OFF_FILE` for `acceptance-gate.off`) whose modification time is under 12 hours old; a stale one is ignored, not deleted. Only a regular file, or a symlink to one (judged by the target), counts; a directory or dangling link is treated as no file. The "expired" note appears in the deny, ask and send-back messages only; the SubagentStart injection stays silent about a stale file.

## Not a hook: run-checks
`run-checks.sh` (logic in `_run_checks.py`) runs a repo's checks for the current commit and writes a stamp file in the worktree's git dir. It is run on request by the `git-verify` skill (`skills/git-verify/SKILL.md`), never from a hook. `_checks_stamp.py` defines check detection and the stamp; it is used by `_run_checks.py` (writes) and, through `_git-guard-check.py`'s `stamp_info`, by git-guard's lease rule and checks-gate (read). Checks come from a `.claude/git-checks` file at the repository root, else the `typecheck`, `lint` and `test` scripts in package.json. `CLAUDE_CHECKS_TIMEOUT` sets seconds per command.

## Not a hook: git-facts
`git-facts.sh` (logic in `_git_facts.py`) prints one JSON object of repository facts for the git skills (see git-workflow-skills.md). Read-only; `--dir <path>`; exits 2 with a JSON error outside a repository.

## Libraries
- `_gate-common.sh`: off switch and off-file expiry. Sourced by delegate-gate, delegate-reminder, require-agent-model, read-size-gate, worktree-gate, git-guard, public-repo-text-gate, shared-db-write-gate; `_handback-common.sh` sources it lazily. If missing, gates stay on.
- `_handback-common.sh`: exempt agent types, send-back cap, report cap, acceptance switch and its off-file. Sourced by context-docs-start, require-acceptance-criteria, handback-gate.
- `_reply-cap-common.sh`: cap, approval phrases, marker paths. Sourced by enforce-response-cap, reply-cap-prompt.
- `_bash-write-check.py`: quote-aware write finder for delegate-gate; its tokenizer is also loaded by `_git-cmd-scan.py`.
- `_git-cmd-scan.py`: git command scanner with cwd tracking (literal paths only). Loaded by `_cmd_dirs.py`, `_git-guard-check.py` (its git-hit rules) and `_public-text-check.py`; unchanged by the unknown-directory work.
- `_cmd_dirs.py`: shared walker, no entry point. `walk(cmd, cwd)` returns every git and gh command on a line, wrapper bodies included, each with its words, subcommand and directory state: `known` (a path), `unknown` (with a short reason) or `temp` (a bare `mktemp -d` on the same line, see the worktree-gate row for what disqualifies it); also `redirect` and the literal `gitdir`/`worktree` for `--git-dir`/`--work-tree`/`GIT_DIR=`/`GIT_WORK_TREE=`, the command's `env` and `-c` config. Also `effective(entry)` (the one place that turns an entry into the directory to judge), `certain_env` (variable resolution: only a standalone literal assignment certain to have run), `prefix_span` (command prefixes), `words_after` (an unquoted `$(...)` is one word), `existing_dir`, `cheap_commands` and `Budget` (lines over the cap), `fed_texts`, `body_guarded`. `legacy=True` is frozen for checks-gate (tests/checks-gate-analyze.pins pins its results; regenerate the pins only from a deliberate change). Used by `_checks-gate-check.py`, `_git-guard-check.py` and `_worktree-gate-check.py`; an import failure disables those gates (fail open). `cd` to a missing directory or after `false &&` is followed as if it ran.
- `_worktree-gate-check.py` (worktree-gate): prints the checkout-changing git commands that must be judged, each as `known` plus directory or `unknown` plus reason.
- `_public-text-check.py` also imports its text extraction from `../hooks/no-agent-mention.py`.
- `_checks-gate-check.py` (checks-gate): decision logic; imports `_cmd_dirs.py`, `_git-guard-check.py` and `_public-text-check.py` (an import failure disables the gate). `checks-gate.conf.example` is its config example.
- `_commit-gate-check.py` (commit-gate) and `_pr-gate-check.py` (pr-gate): decision logic; share `_git_gates_lib.py` (git queries under a 6 s budget, capped reads, config parsing, headings) and `_secret_patterns.py` (the one secret pattern list; a match shows the kind and 6 characters only). They load `_git-cmd-scan.py` and `_public-text-check.py` by path. `bash -c` bodies and aliases are not parsed.
- `_git-guard-check.py` (git-guard), `_public-text-check.py` (public-repo-text-gate), `_sql-write-check.py` (shared-db-write-gate): decision logic.
- Config examples: `shared-db-gate.conf.example`, `public-text-gate.conf.example`, `clock-reminders.conf.example`, `checks-gate.conf.example`, `git-gates.conf.example`.

## Payload fields the scripts read
`hook_event_name`, `cwd`, `tool_name`, `tool_input.command`, `tool_input.file_path`, `tool_input.notebook_path`, `tool_input.limit`, `tool_input.pages`, `tool_input.model`, `tool_input.subagent_type`, `tool_input.prompt`, `tool_input.message`, `agent_id` (present only on subagent calls; the gates use it to tell subagent from main session), `agent_type`, `prompt`, `last_assistant_message`, `stop_hook_active`, `session_id`, `transcript_path`, `scratchpad_dir`.

## Runtime dependencies
- bash everywhere; jq for nearly every script (missing jq means allow, except sync-memory).
- python3 for the Bash-parsing paths: delegate-gate (Bash), worktree-gate, git-guard, checks-gate, commit-gate, pr-gate, public-repo-text-gate, shared-db-write-gate, run-checks, git-facts.
- git: worktree-gate, git-guard, checks-gate, commit-gate, pr-gate, context-docs-start, behavior-doc-reminder, run-checks, git-facts. gh: optional visibility lookup in public-repo-text-gate.

## Design rules (the gate scripts)
- Fail open: malformed input, a missing tool or an undeterminable state exits 0 with no output (a missing `_gate-common.sh` keeps the gate on).
- Deny output is built with a JSON encoder, not string concatenation.
- Gates never modify a repository; git is only queried.
- Environment-specific values live in local config files outside the repo, parsed as data and never sourced; only fake-valued `*.conf.example` files are committed.
- Exceptions: `sync-memory.sh` uses `set -euo pipefail` and exits non-zero without jq. `behavior-doc-reminder.sh` exits 1 when run without its mode argument and keeps a state file under `/tmp`. Some denial and reminder texts are written for one specific user.
