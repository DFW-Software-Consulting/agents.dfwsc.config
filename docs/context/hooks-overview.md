# Hook scripts

This repository only tracks the scripts. Which of them are registered is decided by settings files outside the repository (the repo's `ai-code-agents/claude/settings.json` registers only `no-agent-mention.py`), so you cannot tell from the repo which hooks are active: check your own settings. "Event" below is where a script is meant to be registered, from its header comment, which is the detailed spec.

Scripts live in `ai-code-agents/claude/local-hooks/`, `hooks/` and `personal-hooks/`.

## Scripts

| delegate-gate.sh | PreToolUse, Edit/Write/NotebookEdit (and Bash) | Denies file edits from the main session; on Bash denies redirects to files, tee, `sed -i`, `perl -i`, `awk -i inplace`. | worktree-gate.sh | PreToolUse, Edit/Write/NotebookEdit and Bash | Denies edits and HEAD/index/worktree-changing git commands in a primary checkout. Limits: nesting deeper than 3, aliases, `xargs`/`find -exec`/`ssh` and text fed to a shell (`echo 'cd <path> && git commit'` piped into bash; git-guard does follow it for its text-only rules) are not followed | CLAUDE_WORKTREE_GATE=off or 12h off-file |
| git-guard.sh | PreToolUse, Bash | Denies hook bypass (`--no-verify`, `commit -n`, `HUSKY=0`, core.hooksPath), force push, push to the default branch. An unparseable wrapper body that holds a push or hook bypass is denied (`unparsed-body`). When the directory is unknown (variable not certain, substitution, `cd -`, explicit git dir, even a `mktemp -d` one: a clone there can still push to a real remote) a push is denied if it names `main` or `master` (also `heads/main`), names no destination (bare `git push`, `git push origin`, `HEAD`, `@`, a bare `:`), and allowed if it names another branch, `--repo=<remote> feat` or `tag v1`; the lease rule already denied an unknown directory. Limits: nesting deeper than 3, aliases, `xargs`/`find -exec`/`ssh`, text a shell reads from a file or a command's output are not followed; with an unknown directory only `main` and `master` are known as default branch names | CLAUDE_GIT_GUARD=off or 12h off-file |
| checks-gate.sh | PreToolUse, Bash | Before `git push` and `gh pr create`, wants a valid check stamp for HEAD; warns (default) or denies by `~/.claude/checks-gate.conf` (`MODE`, `DENY_AFTER`). Skips dry-run, delete, tags-only, other refs, `gh pr create --repo`. When the directory cannot be established (a `cd`, `pushd`, `-C`, `--git-dir`, `--work-tree` or `GIT_DIR=` with a variable or substitution, `cd -`, `popd`, or a `bash -c`/`sh -c`/`eval` body doing so) it denies or warns that it could not tell which repository the command runs in; only text-only exemptions (dry-run, delete, tags-only) still apply, and a plain literal assignment earlier in the line (`W=/path; cd "$W"`) is resolved. Variables resolve only from a standalone literal assignment certain to have run (not a prefix assignment, not inside if/loop/function/subshell/pipeline, not after an and-or operator following another command, not after unset/read/+=/declare/let/`(( ))`/...); any `--git-dir`, `--work-tree`, `GIT_DIR=` or `GIT_WORK_TREE=` on a push also counts as unknown. A line with over about 300 git/gh/cd/shell words is not walked (the walker is quadratic): a push or `gh pr create` on it counts as an unknown directory, otherwise it is silent (4,000 commands: about 50 ms). Walker: `_cmd_dirs.py` (legacy mode, behaviour unchanged; a `mktemp -d` directory counts as unknown here). Limits: an unparseable command line, `bash -c`/`eval` nesting deeper than 3, aliases, `xargs`/`find -exec`/`ssh` wrappers lines over about 128 KB and word splitting under a changed `IFS` are not scanned; a `cd` to a missing directory or after `false &&` is followed as if it ran (as before). Read-only | CLAUDE_CHECKS_GATE=off |
| commit-gate.sh | PreToolUse, Bash | Before `git commit` (not `--dry-run`). Denies: secret file names (`.env`, `.env.*`, `*.pem`, `*.key`, `id_rsa*`, `id_ed25519*`, `credentials.json`, `*.p12`, `*.pfx`; not `.env.example` style files or `*.pub`; `.npmrc` only with a literal `_authToken`), conflict markers (both `<<<<<<< ` and `>>>>>>> ` in added lines, not in docs files), a high-confidence secret in added lines or in the message. Judges staged paths, `commit -a`, a path-limited commit (named paths only), and files a same-line `git add` will stage (a glob or non-literal argument counts like `add -A`). Warns only (never denies) on subject format where the repo already follows `type(scope): description`. A file with over 2 MB of added text (or an `.npmrc` over 64 KB) is skipped with a warning naming how many files were not scanned; the rest are still scanned, however large their neighbours are (skipped files do not use the scan budget). A path the commit deletes is never judged. A path-limited commit of a directory or glob also covers staged files; a repository with no commits is compared with the empty tree. The directory comes from the shared walker `_cmd_dirs.py` (payload cwd followed through `cd`, `pushd`, `git -C`, `env -C`, plain variable assignments certain to have run, `GIT_DIR=`/`--git-dir` judged by the work tree, `bash -c`/`sh -c`/`eval`/`env -S` bodies three levels deep), so `W=<path> && cd "$W" && git commit` is judged like the literal path. A commit whose directory cannot be established (variable not certain, substitution, `cd -`, `popd`, variable git directory, an unparseable wrapper body holding a commit, a line over about 300 commands or 0.4 s) is denied: the gate could not tell which repository, so the staged content cannot be inspected, write the directory literally. A directory made by a bare `mktemp -d` on the same line is allowed (its content is not inspected). The message secret scan runs on the message text whatever the directory state. A literal directory that does not exist or is not a repository, a payload with no cwd (message scan only) and `--dry-run` are not judged. Config `~/.claude/git-gates.conf` (`ALLOW_PATHS`). Read-only, fail open. On a line over the analysis budget a `bash -c`/`sh -c`/`eval`/`env -S` body holding a commit is denied as unknown, and the message and body text is still scanned for secrets. An explicit git directory of a linked worktree is judged by that worktree (the one recorded in its `gitdir` file), unknown (denied) when that cannot be read. `-h` and `--help` skip the commit only in option position (`-m -h` is a message). Without `_cmd_dirs.py` the gate falls back to the previous literal-directory scan and writes one line to standard error. Limits: aliases are not followed; A `cd` that would fail or not run is still followed; nesting deeper than three levels, lines over about 128 KB and text piped into a shell are not judged. | CLAUDE_GIT_GUARD=off or the git-guard 12h off-file |
| pr-gate.sh | PreToolUse, Bash | On `gh pr create`, `gh issue create` and `gh pr edit` with a body or title. Always denies: `gh pr create` from a head branch that is not pushed and in sync (judged from `refs/remotes/<push remote>/<branch>`, else a differently named upstream; an upstream that is the default branch does not count as pushed), and a secret in the title or body. By mode (`PR_GATE_MODE=warn` default, `deny`, `PR_GATE_DENY_AFTER`): missing template sections, unfilled template placeholders, a diff over the size cap without a Split plan or `LOC-exception:`. Skips `--web`, `--fill*`, `--template` and unreadable bodies. The secret rule runs for every recognised create or edit, whether or not a directory or repository resolves (a non-repository directory, a missing `cd` target, an override, an explicit git dir). A repository override (`-R`, `--repo`, any spelling, before or after `create`, flag parsing stops at `--`, and the secret rule still scans the words after it; or `GH_REPO` in the command's environment, the flag winning) naming another repository runs only that rule, since the branch, template and diff read here belong to a different repository; the override is compared with the directory's own repository after dropping `.git`, scheme, host and user, in any letter case (`OWNER/REPO`, `HOST/OWNER/REPO`, URLs, `user@host:owner/repo`), and a value that is not a literal after same-line resolution may be the own repository, so all rules run (and an unknown directory is denied). Commands and directories come from `_cmd_dirs.py` (variables, `pushd`, `env -C`, wrapper bodies three levels deep). A secret in a title or body is judged from the text whatever the directory. When the directory cannot be established (variable not certain, substitution, `cd -`, `popd`, an unparseable wrapper body holding `gh pr create`, a line over the analysis budget) `gh pr create` is denied: could not tell which repository, write the directory literally, except in the forms skipped above, `--head owner:branch` and a `-R`/`--repo` (not judged against an unknown directory); the template, placeholder and size rules are skipped (they need the repository), and `gh issue create` and `gh pr edit` get the secret rule only. A temporary directory (bare `mktemp -d`) or a payload with no cwd: secret rule only, no denial. The secret rule also runs on any title or body text in the forms the gate skips (`--web`, `--fill*`, `--template`, `-f`, no body, an unreadable body: the title is still judged), and `-R=owner/repo` is read like `-R owner/repo`; these only turn a previously allowed command into a denial when a secret is present. On a line over the analysis budget a wrapper body holding `gh pr create` is denied as unknown and secrets in the body text are denied. Without `_cmd_dirs.py` the gate falls back to the previous literal-directory scan and writes one line to standard error. Limits: a relative `--body-file` or a body from a variable cannot be read with an unknown directory (that body is not judged); `GIT_DIR=<git dir> gh pr create` (also `env`, `export`, a same-line variable) is judged as a git dir: the push rule reads that git dir's own HEAD and upstream (bare repositories, separate git dirs, symlinks and linked worktree git dirs included), `GIT_WORK_TREE` only supplies the work tree for the template rules (skipped when none can be told, so for a bare repo), `GIT_WORK_TREE` alone leaves the directory's repository judged; a literal value that is not a git dir or an unresolvable `GIT_DIR` is denied as unknown. When the gate cannot be certain `GIT_DIR` reaches gh (assigned without `export`, exported and then `unset`, `env -u`/`-i`, a subshell or `bash -c` that unsets it, a conditional export) it judges both the directory's repository and the target and denies if either is denied; prefix, `env VAR=` and a lone `export` judge the target only. Without `_cmd_dirs.py` any command that loosely reads `gh ... pr or issue ... create` has its whole text scanned for secrets and a notice that the walker is missing is part of the output. A `cd` that would fail or not run is still followed; nesting deeper than three levels, lines over about 128 KB and text piped into a shell are not judged. Local refs only, no network. Config `~/.claude/git-gates.conf` (`SOP_REPOS`, `SOP_PR_TEMPLATE`, `SOP_ISSUE_TEMPLATE`, `OPTIONAL_HEADINGS`, `LOC_CAP`, mode keys); `git-gates.conf.example`. Skipped on a detached HEAD; empty sections pass | CLAUDE_PR_GATE=off |

## Not a hook: run-checks
`run-checks.sh` (logic in `_run_checks.py`) runs a repo's checks for the current commit and writes a stamp file in the worktree's git dir. It is run on request by the `git-verify` skill (`skills/git-verify/SKILL.md`), never from a hook. `_checks_stamp.py` defines check detection and the stamp; it is used by `_run_checks.py` (writes) and, through `_git-guard-check.py`'s `stamp_info`, by git-guard's lease rule and checks-gate (read). Checks come from a `.claude/git-checks` file at the repository root, else the `typecheck`, `lint` and `test` scripts in package.json. This repo has a `.claude/git-checks` that runs `run-tests.sh`. `CLAUDE_CHECKS_TIMEOUT` sets seconds per command.

## Not a hook: git-facts
`git-facts.sh` (logic in `_git_facts.py`) prints one JSON object of repository facts for the git skills (see git-workflow-skills.md). Read-only; `--dir <path>`; exits 2 with a JSON error outside a repository.

## Libraries
- `_gate-common.sh`: off switch and off-file expiry. Sourced by delegate-gate, delegate-reminder, require-agent-model, read-size-gate, worktree-gate, git-guard, public-repo-text-gate, shared-db-write-gate; `_handback-common.sh` sources it lazily. If missing, gates stay on.
- `_handback-common.sh`: exempt agent types, send-back cap, report cap, acceptance switch and its off-file. Sourced by context-docs-start, require-acceptance-criteria, handback-gate.
- `_reply-cap-common.sh`: cap, approval phrases, marker paths. Sourced by enforce-response-cap, reply-cap-prompt.
- `_completion-gate-check.py` (completion-gate, Stop): worktree scan, stamp check, statement match; imports `_checks_stamp.py`; sources `_gate-common.sh` in the shell part. `completion-gate.conf.example` is its config example.
- `_bash-write-check.py`: quote-aware write finder for delegate-gate; its tokenizer is also loaded by `_git-cmd-scan.py`. It imports `_cmd_dirs.py` lazily (`certain_env`, `subst`, `trace`) to resolve variable targets and to scan command bodies; no import means literal targets only.
- `_git-cmd-scan.py`: git command scanner with cwd tracking (literal paths only). Loaded by `_cmd_dirs.py`, `_git-guard-check.py` (its git-hit rules) and `_public-text-check.py`; unchanged by the unknown-directory work.
- `_cmd_dirs.py`: shared walker, no entry point. `walk(cmd, cwd)` returns every git and gh command on a line, wrapper bodies included, each with its words, subcommand and directory state: `known` (a path), `unknown` (with a short reason) or `temp` (a bare `mktemp -d` on the same line, see the worktree-gate row for what disqualifies it); also `redirect` and the literal `gitdir`/`worktree` for `--git-dir`/`--work-tree`/`GIT_DIR=`/`GIT_WORK_TREE=`, the command's `env` and `-c` config. Also `effective(entry)` (the one place that turns an entry into the directory to judge), `gate_entries`, `gate_dirs`, `gh_variants` (the repositories pr-gate judges a gh entry against, from the entry's `xgd`/`xwt`/`xmaybe`; `redirect` stays unset on gh entries so other gates are unchanged) and `explicit_work_dirs` (what commit-gate, pr-gate and public-repo-text-gate use: known, temp, unknown or none per entry; `cheap_gates` covers lines over the budget), `_lex`/`_restore` (one linear pre-pass, inside this file: finds every outermost substitution (`$( )`, backticks, `<( )`, `>( )`) and every here-document body, knowing quotes, `$'...'`, comments, `case` patterns, `${ }` and `$(( )`; each substitution becomes a placeholder inside its word so the tokenizer never splits a word at it, and the words are restored to the original text afterwards, so `git -C $(pwd)/a push` keeps its subcommand, `sudo -u $(id -un)x git push` and `timeout $(echo 5)s git push` are seen, and secret and public-text rules read the text as written; the command text inside each substitution, double-quoted ones and unquoted here-document bodies included, is walked at the token that holds it with the line's certain variables seeded; not in legacy mode; nesting over 16 in any frame (`${ }`, `$(( ))`, double quotes included), an unclosed quote or substitution, or any failure inside the lexer makes the whole line one `body` entry that the gates judge as text, so an unparseable line fails closed; an unquoted `${ }` is a span of its own so the tokenizer never counts its braces; here-document delimiters are read like the shell reads them; `$[ ]`, an array subscript and a comment after a line continuation open no here-document; `cheap_commands`/`cheap_gates` read the commands inside substitutions too; remaining limits are listed in the module docstring and errors.md), `_tokens` (tokens plus the substitutions each holds), `certain_env` (variable resolution: only a standalone literal assignment certain to have run; `certain_literal` rejects `$`, backticks, globs, brackets, braces, backslashes, `:~` and foreign tildes (a `<(` or `>(` inside an assignment word also makes the name unknown; a quoted value with brackets or braces is unknown too, since quoting is not tracked), and a later non-literal assignment makes the name unknown), `prefix_span` (command prefixes), `words_after` and `prefix_span` (a redirection inside a command or before it, `git 2>&1 push`, `2>&1 git push`, `sudo 2>&1 git push`, is skipped instead of ending it), `existing_dir`, `cheap_commands` and `Budget` (lines over the cap), `fed_texts`, `body_guarded`. `legacy=True` is frozen for checks-gate (tests/checks-gate-analyze.pins pins its results; regenerate the pins only from a deliberate change). `trace(cmd, cwd)` is an additive entry point returning each git/gh command with the variables certain at that point plus the text of every followed body (outer assignments handed to a `bash -c` body); `walk()` results are unchanged by it. Used by `_checks-gate-check.py`, `_git-guard-check.py`, `_worktree-gate-check.py`, `_commit-gate-check.py`, `_pr-gate-check.py` and `_public-text-check.py`; an import failure disables those gates (fail open). Also loaded by path from `../hooks/no-agent-mention.py` and `_bash-write-check.py`, which fall back to their old behaviour without it. `cd` to a missing directory or after `false &&` is followed as if it ran.

- `_public-text-check.py` also imports its text extraction from `../hooks/no-agent-mention.py`.

- bash everywhere; jq for nearly every script (missing jq means allow, except sync-memory).
- python3 for the Bash-parsing paths: delegate-gate (Bash), worktree-gate, git-guard, checks-gate, commit-gate, pr-gate, public-repo-text-gate, shared-db-write-gate, brain-schema-hint, run-checks, git-facts.

## Design rules (the gate scripts)
- Fail open: malformed input, a missing tool or an undeterminable state exits 0 with no output (a missing `_gate-common.sh` keeps the gate on).
- Deny output is built with a JSON encoder, not string concatenation.
- Gates never modify a repository; git is only queried.
- Environment-specific values live in local config files outside the repo, parsed as data and never sourced; only fake-valued `*.conf.example` files are committed.
- Exceptions: `sync-memory.sh` uses `set -euo pipefail` and exits non-zero without jq. `behavior-doc-reminder.sh` exits 1 when run without its mode argument and keeps a state file under `/tmp`. Some denial and reminder texts are written for one specific user.
